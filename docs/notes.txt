# Спрайты оружия в BMP (4-бит)

Спрайты оружия можно хранить как индексированные BMP (4 или 8 бит, BI_RGB,
без сжатия) рядом с PNG — загрузчик сначала пробует `*.bmp`, потом PNG.

Особенности:
- палитровый индекс 0 = прозрачность;
- палитра НЕ запекается в пиксели: в `Weapon` хранятся индексы + палитра,
  и изображение пересобирается через `Texture.createColorPalettes` —
  оружие светлеет/темнеет по `SectorData.getLightLevel()` текущего сектора
  (как текстуры мира), пересборка только при смене уровня света;
- конвертация PNG→BMP4: `scripts/png_to_bmp4.py` (чистый stdlib),
  сгенерированные BMP лежат рядом с PNG в `res/gamedata/sprites/`.

src/BMPLoader.java — порт https://github.com/rmn20/l2d_m3g/blob/master/src/com/BMPLoader.java
с добавленной поддержкой 4-бит и без зависимости от M3G.

# Формат ресурсных файлов (проверен по бинарным файлам 10.08.2026)

## level_XX (карта уровня), little-endian
1 байт версии, затем секции: вершины (4b), описания стен (11b), объекты (10b),
плоскости стен (8b), сектора (12b), BSP-узлы (12b), BSP-листья (4b),
сегменты стен (9b), битовая матрица видимости. Каждая секция начинается
с int32LE — размера секции в байтах.

## tx1..tx4 (атлас текстур стен/полов), big-endian
Заголовок: magic u16 = 0x9954, entries u16, palettes u16, pixelDataOffset u32.
Запись (header 9 байт!): id u8, w u16, h u16, paletteOffset u16, bitDepth u16.
Далее упакованные пиксели ceil(w*h*bitDepth/8) байт, потом блок палитр по
pixelDataOffset: [colorCount u32][color u32 x N].
- id > 0: стены (w x 128) ЛИБО спрайты пола/потолка 64x64 (bitDepth 2/3/4)
- палитра привязана позиционно: paletteOffset = индекс палитры в этом файле

## sp1..sp4 (атлас спрайтов объектов/врагов), big-endian
Заголовок: magic u16 = 0x9953, entries u16, palettes u16, pixelDataOffset u32.
Запись (header 13 байт!): id u8, w u16, h u16, hOff s16, vOff s16,
paletteOffset u16, bitDepth u16. id < 0 — текстуры объектов (column-major),
hOff/vOff — якорные смещения для билбордов (PortalRenderer).
Палитры — как у tx.

ВНИМАНИЕ: парсер ОБЯЗАН использовать header 9 байт для tx и 13 байт для sp.
Смешанный 13-байтный парсер для tx съезжает и уходит в вечный цикл
skipBytes() = бесконечный "Loading" (баг, исправлен 10.08.2026).

# Редактор уровней (10.08.2026)

`scripts/level_editor.py` — GUI на чистом tkinter (зависимостей нет;
на Linux при необходимости `sudo apt install python3-tk`). Запуск из
корня репо: `python3 scripts/level_editor.py [res/gamedata/levels/level_01a]`.

`scripts/co3d_level_core.py` — headless-ядро (парсинг/запись карт и
атласов, ребилд BSP/PVS, софтверный 3D-рендер). Быстрый selftest:
`python3 scripts/co3d_level_core.py selftest res/gamedata`;
полный набор проверок: `python3 scripts/test_co3d_core.py`.

Уточнения формата карты, добытые при написании редактора:
- запись сегмента стены (9 байт): sv u16, ev u16, **defIdx u16**, ff u8
  (0 = front-сторона), **texOff u16**. В LevelLoader.loadMapData имена
  локальных переменных перепутаны: 3-й short файла уходит в конструктор
  как defIndex, последний — как texOffset. Back-сегменты ориентированы
  противоположно (ev->sv); при разрезании стены BSP-строителем texOff
  копит длину вдоль цепочки (в мировых единицах, 1:1).
- узел BSP = линия сегмента: (splitX, splitZ) — старт, (normalX, splitDy) =
  (dx, dz) к концу. Дети: frontChild — полуплоскость cross>0, backChild —
  cross<=0 (игра: isPointInFront==true -> backChild). Корень — ПОСЛЕДНИЙ
  узел массива (поиск начинается с bspNodes[nodes-1], как в Doom).
- сектор листа = сектор его первого сегмента (через surface.sectorLinkId,
  беззнаковый байт). Все листья стоковых карт сектор-чистые.
- PVS: битовый поток, бит i = col*n+row, LSB-first, row быстрее;
  1 = сектор НЕ виден (visitedFlags-семантика). Редактор при перестройке
  пишет консервативную матрицу «всё видно» (все нули) — корректно, просто
  чуть дороже по кадру.

Построитель BSP в редакторе (Doom-style, чистый Python):
- исходные сегменты: по одному на сторону стены (front sv->ev ff=0,
  back ev->sv ff=1), без сплитов;
- сплиттер — минимум (разрезы*8 + |дисбаланс|) из до 24 равномерных
  кандидатов; коллинеарные сегменты (включая близнецов двусторонних стен)
  разводятся по ЛИЦЕВОЙ нормали (сектор всегда СПРАВА от направления
  сегмента — проверено на стоке 790/790);
- разрезы добавляют вершины с коплением texOff по длине;
- валидация после постройки: спуск по дереву для внутренних точек каждого
  сектора сравнивается с геометрическим эталоном (на стоке 0 расхождений
  на всех 13 картах; точки на самих границах и объекты эталоном не служат —
  там даже сток отличается от even-odd);
- уровень из одного сектора: синтезируется тривиальный узел с двумя
  листьями (игра без узлов упала бы).

3D-превью в редакторе — секторный рейкаст по колонкам (не зависит от BSP):
стены с main/upper/lower текстурами, свет из light сектора, небо по id 51
(tx-25), полы/потолки плоские или текстурированные (переключение F),
билборды объектов из sp-атласов (индекс 0 = прозрачность), спавн-позиция
и угол как в игре (-rawAngle*1144+102943).

Композитные текстуры: в атласах их НЕТ, игра собирает из базовых
(Texture.compositeTexture — региональное копирование, не альфа): 39/40 из
35, 47/48 из 46, 50 из 49 (rect-списки в co3d_level_core._COMPOSITES,
скопированы из LevelLoader.loadGameAssets) — палитра базы.
